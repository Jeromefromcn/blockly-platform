# Dev Log - 2026-03-22

## Summary

Major development day for the Blockly Exercise Platform. Completed the auto-grading system, ZIP batch import, CSV export, Run button for both tutor and student views, allowed-blocks restriction per exercise, and a series of bug fixes. Also enforced English-first policy across the codebase and reorganized dev-log structure.

## Design Decisions

- **Auto-grading via Mozilla Rhino**: Chose backend JS execution (Rhino engine) over frontend execution or structural code comparison. This gives the most accurate correctness judgment regardless of how the student arranged Blockly blocks.
- **Two grading modes**: OUTPUT_MATCH (compare printed output against expected) and TRACE_MATCH (compare execution trace array). Tutors select the mode per exercise at creation time.
- **Dual print compatibility**: Old Blockly exports use `window.alert()`, new ones use `print()`. Fixed at two layers — frontend overrides the Blockly generator to emit `print()`, and backend mocks both `print()` and `window.alert()` in the Rhino sandbox.
- **clientId for like deduplication**: No login system exists, so browser localStorage UUID is used to prevent duplicate likes. Cancel-like feature was intentionally dropped for simplicity.
- **Allowed blocks per exercise**: Tutors can restrict which Blockly block categories students can access, enforced via filtered toolbox in the frontend.
- **Dev log structure**: English logs in `dev-log/` root, Traditional Chinese logs in `dev-log/zh/`. English-first policy applied to all code, comments, and documentation.

- **GradingService**: Auto-grade on batch/ZIP import when `generatedCode` is present; ZIP import endpoint; CSV grade export.
- **SubmissionController**: `/import-zip` and `/export-csv` endpoints.
- **ExerciseVersion**: Added `grading_mode` and `allowed_blocks` fields.
- **Grade**: Added `auto_score` field.

- **AdminEditor (frontend)**: Run button, grading mode dropdown, test cases / trace input, allowed-blocks checkboxes.
- **Workspace (frontend)**: Run button with output panel; exports `generatedCode` in submission JSON.
- **Admin (frontend)**: Shows `autoScore` badge in submissions list and as read-only reference in grade modal.
- **index.html**: Changed `lang` to `en`, title to English.
- **TEST_CASES.md / TEST_CASES_ZH.md**: Documentation for test case formats.
- **Unit tests**: 8 tests in AutoGradingServiceTest, 4 in ExerciseServiceTest.

## Bug Fixes

- `window.alert` not defined in Rhino sandbox → auto_score always 0. Fixed by mocking `window.alert` in AutoGradingService and overriding the Blockly `text_print` generator.
- Student export missing `generatedCode` → auto-grading had nothing to execute. Fixed by adding `generatedCode: wsRef.current.getCode()` to the Workspace export payload.
- Admin UI not showing `autoScore` → tutors had no reference during manual grading. Fixed in Admin.jsx.
- Dev log file naming: reorganized from `en/` and `zh/` subfolders to English at root and Chinese under `zh/`.

## Discussion Conclusions

- Auto-grading is backend-side only; frontend execution was rejected due to security and consistency concerns.
- Cancel-like feature was dropped — clientId-based single-direction like is the accepted approach.
- All code, comments, and documentation strings must be in English. Chinese is only permitted in conversation and the `dev-log/zh/` logs.
- Sub-agent delegation pattern: main Claude thread stays free for conversation; dev tasks are delegated to sub-agents.
