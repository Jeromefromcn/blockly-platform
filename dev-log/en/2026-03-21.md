## Design Decisions

### Like System
- **Decision:** Use `clientId` (a UUID stored in the browser's `localStorage`) to identify per-browser like actions, without requiring user authentication.
- **Decision:** Changed to single-direction like (no unlike/cancel). Cancelling a like would require an auth system to verify ownership, which is not yet implemented.
- A `client_id` column with a unique constraint was added to the database to enforce deduplication at the data layer.

### Auto-Grading System
- **Decision:** Execute student JavaScript on the backend using the Mozilla Rhino engine, rather than in a front-end browser sandbox. Backend execution is more reliable, consistent, and auditable — results are not affected by the student's browser environment.
- Two grading modes:
  - `OUTPUT_MATCH`: Runs test case expressions and compares return values. Tutors define test cases as a JSON array: `[{"input": "expression", "expected": "value"}]`
  - `TRACE_MATCH`: Runs the full program and compares the execution trace array against an expected trace.
- Auto-grading is triggered on: single JSON import and ZIP batch import.

### Confirmed Grading Workflow
The full end-to-end workflow was formally agreed upon:
1. Tutor creates exercises on the new platform
2. Student completes exercises on the new platform
3. Student exports their work as JSON (includes `generatedCode` field)
4. Student uploads JSON to school LMS (e.g. Moodle)
5. Tutor downloads submissions from LMS
6. Tutor batch-imports ZIPs into the new platform → auto-grading runs automatically
7. Tutor performs manual review
8. Tutor exports a CSV grade sheet

## Bug Fixes

### Blockly `text_print` Block Compatibility
- **Problem:** Blockly's `text_print` block generates `window.alert()` by default. The Mozilla Rhino engine has no `window` object, causing backend auto-grading to throw a `ReferenceError` and fail.
- **Fix 1 (frontend):** In `BlocklyWorkspace.jsx`, overrode the `text_print` code generator to emit `print()` instead of `window.alert()`.
- **Fix 2 (backend):** In `AutoGradingService.java`, mocked both `print()` and `window.alert()` in the Rhino scope to ensure backward compatibility with any previously exported code that still contains `window.alert()`.
- Files: `BlocklyWorkspace.jsx`, `AutoGradingService.java`

## Discussion Conclusions

### Auto-Grading Architecture
- Backend execution via Rhino is the correct approach over front-end browser sandbox execution: results are consistent, auditable, and independent of the student's environment.
- `OUTPUT_MATCH` is suitable for exercises where a specific return value or printed output is expected.
- `TRACE_MATCH` is suitable for algorithm tracing exercises where the sequence of intermediate values matters.
