# 開發日誌 - 2026-03-22

## 摘要

Blockly 練習平台的重要開發日。完成了自動評分系統、ZIP 批量導入、CSV 成績導出、師生端執行按鈕、允許積木類別限制功能，以及一系列 Bug 修復。同時強制執行了英文優先政策並重新整理了開發日誌結構。

## 設計決策

- **使用 Mozilla Rhino 進行自動評分**：選擇後端 JS 執行（Rhino 引擎）而非前端執行或結構比對，能最準確地判斷代碼正確性，不受積木排列方式影響。
- **兩種評分模式**：OUTPUT_MATCH（比對輸出結果）和 TRACE_MATCH（比對執行追蹤陣列）。出題時由教師選擇模式。
- **雙重輸出相容性**：舊版 Blockly 導出使用 `window.alert()`，新版使用 `print()`。前端覆蓋積木生成器輸出 `print()`，後端同時模擬兩者。
- **clientId 防重複 like**：無登入系統，使用 localStorage UUID 防止重複點讚。取消點讚功能因簡化需求而捨棄。
- **每題允許積木限制**：教師可限制學生可用的積木類別，前端通過過濾工具箱執行。
- **開發日誌結構**：英文日誌放 `dev-log/` 根目錄，繁體中文放 `dev-log/zh/`。所有代碼強制英文優先。

## 功能開發

- **AutoGradingService**：Rhino 沙箱執行；支援 OUTPUT_MATCH 和 TRACE_MATCH；模擬 `print()` 和 `window.alert()`。
- **GradingService**：批量/ZIP 導入時自動評分；ZIP 導入端點；CSV 成績導出。
- **SubmissionController**：新增 `/import-zip` 和 `/export-csv` 端點。
- **ExerciseVersion**：新增 `grading_mode` 和 `allowed_blocks` 欄位。
- **Grade**：新增 `auto_score` 欄位。
- **Like**：新增 `client_id` 欄位及唯一約束。
- **AdminEditor（前端）**：執行按鈕、評分模式下拉、測試用例/追蹤輸入、允許積木複選框。
- **Workspace（前端）**：執行按鈕及輸出面板；提交 JSON 包含 `generatedCode`。
- **Admin（前端）**：提交列表顯示 `autoScore`，評分模態框顯示自動分數參考。
- **TEST_CASES.md / TEST_CASES_ZH.md**：測試用例格式文檔。
- **單元測試**：AutoGradingServiceTest 8 個，ExerciseServiceTest 4 個。

## Bug 修復

- Rhino 沙箱中 `window.alert` 未定義 → 自動分數恆為 0。在 AutoGradingService 模擬 `window.alert` 並覆蓋 Blockly `text_print` 生成器修復。
- 學生導出缺少 `generatedCode` → 自動評分無代碼可執行。在 Workspace 導出 payload 加入 `generatedCode` 修復。
- Admin UI 未顯示 `autoScore` → 教師手動評分無參考依據。在 Admin.jsx 修復。
- 開發日誌命名重整：從 `en/` 和 `zh/` 改為英文放根目錄、中文放 `zh/`。

## 討論結論

- 自動評分在後端執行，前端執行因安全性和一致性問題被否決。
- 取消點讚功能捨棄，採用 clientId 單向點讚方案。
- 所有代碼、注釋、文檔字符串必須使用英文，中文僅限對話和 `dev-log/zh/` 日誌。
- 子 Agent 委派模式：主 Claude 線程保持對話狀態，開發任務委派給子 Agent。
